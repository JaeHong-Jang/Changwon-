> 이 문서를 커밋한 뒤에 과거 발표 예보와 침수 기록을 맞춰 보는 평가를 시작한다.
> 커밋 이후 바꾸는 내용은 §9 변경 기록에 시각과 이유를 남기고, 평가 결과를 본 뒤의 변경은 `post-hoc` 으로 표기한다.

## 1. 질문, 결과변수, 해석 범위

- 질문: 기상청이 발표한 단기예보 강수로 (1) 관측 기준 호우가 된 사상에서 창원시 침수 **기록**이 생길지, (2) 생긴다면 어느 100 m 격자에서 생길지를 미리 알 수 있는가.
- 결과변수는 **행정 침수흔적 기록**이다. 물리적 침수나 피해액이 아니다.
  - 사상 단위 `E_t`: 호우 t 의 라벨 창(§3)에 확보한 인벤토리의 흔적 폴리곤이 1개 이상 연결된다.
  - 격자 단위 `Y_it`: 호우 t 에 연결된 흔적을 기존 규칙(`FT.label_grid`, 겹침 10%)으로 격자화했을 때 격자 i 가 양성이다.
- 결합 확률 `P(Y_it = 1) = P(E_t = 1 | 예보) × P(Y_it = 1 | E_t = 1, 지형)` 은 **기록 침수의 결합 확률**로만 해석한다.
  모형 가정: 강우량에 따라 침수 위치·면적이 달라지는 효과는 두 번째 항에 넣지 않는다. E = 1 이지만 양성 격자가 없는 사상도 평가에 남긴다.
- 해석 범위: 주 분석은 **관측 호우 기준을 충족한 사상에 조건부인 후향 평가**다. 전체 예보의 오경보율이나
  침수 전 선행시간을 뜻하지 않는다. t0 는 강우 시작이 아니라 관측 임계 최초 도달시각이며, 침수 시작시각이 없는 사상에서 선행시간을 주장하지 않는다.

## 2. 호우 목록 (모집단)

- 입력: 파이프라인이 만든 `data/processed/canonical/rainfall_hourly.parquet` 의 `quality_flag == "ok"` 값. 창원시 우량계 36지점, 2005-01-01 ~ 2025-09-17.
- 시간은 KST. 시각 t 의 시간강수는 직전 한 시간 (t−1h, t] 의 양이다. 누적창은 (t−h, t] 이며 창 안에 결측이 하나라도 있으면 그 누적값은 쓰지 않는다.
- **호우 시각**: 한 지점이라도 3시간 ≥ 60 mm 또는 12시간 ≥ 110 mm (기상청 호우주의보 강수 기준).
- **호우 사상**: 정렬한 호우 시각에서 이웃 간격이 72시간 이하이면 같은 연결성분(사상)이다 (72 는 합침, 73 은 나눔). 첫 호우 시각 `t0`, 마지막 `t1`.
- 관측 특징: `r12max_obs` = [t0−12h, t1] 안 모든 지점·시각의 12시간 누적 최댓값. `r3max_obs` 는 기술통계로만 쓴다.
- 우량계 수가 2005~2009년 6~8지점, 2010년 이후 19~34지점으로 바뀐다. 주 분석은 가용 지점 전체를 쓴다.
  민감도 목록은 2006~2025년 매해 가동률 ≥ 95% 인 고정 지점만 쓴다. 가동률 분모는 그해 예정 시간 수(2025년은 09-17 24시까지)이며,
  조건을 채우는 지점이 없으면 "분석 불가"로 보고한다.

## 3. 사상 라벨과 역할

- 라벨 창: [date(t0) − 1일, date(t1) + 1일], 양 끝 포함. 흔적 `event_date` 가 창에 들면 연결한다.
- 인벤토리 범위 (양 끝 포함)
  - 개발: 2006-01-01 ~ 2019-12-31 (DSSP-IF-00117), 2025-01-01 ~ 2025-09-17 (창원시 NDMS)
  - 홀드아웃: 2022-01-01 ~ 2024-12-31 (창원시 정보공개, `AGENTS.md` §2-2)
- 역할은 **라벨 창 전체**가 한 범위 안에 들 때만 붙인다. 창이 범위 경계를 넘거나 범위 밖이면 `uncovered` 로 라벨 없이 개수만 보고한다.
- 흔적이 없는 호우는 결과변수 정의상 음성(기록 없음)이다.
- 날짜가 없는 흔적, 두 사상 이상의 창에 걸치는 흔적은 **어느 사상에도 배정하지 않고** 제외 사유와 함께 보고한다.
  어떤 사상에도 연결되지 않는 흔적(기준 미만 강우 침수·날짜 오류)은 목록 누락으로 보고한다.
- 사상별 격자 라벨은 연결된 흔적만으로 다시 만든다. 연도별 라벨(`trace_ev_<year>`)을 여러 사상에 복제하지 않는다.
  (`trace_ev_<year>` 는 기존 공간 모형의 학습 라벨로만 쓴다.)
- 민감도 S2: 호우 목록과 인벤토리로만 정한다 — 그 역할의 인벤토리가 그해 양성 사상을 1건 이상 기록한 해의 음성과 모든 양성.
  S2 는 결과에 따라 연도를 고르는 분석이어서 주 모집단의 성능을 대표하지 않으며, 홀드아웃 S2 결과로 규칙을 다시 고르지 않는다.
- 홀드아웃 흔적을 읽는 실행은 리더만 한다.

## 4. 기상청 자료 (평가 입력)

- 단기예보 격자 (API허브 `nph-dfs_shrt_grd`, 5 km, 149 × 253, 결측 −99).
  - 발표본은 **예정 발표시각**(매일 02·05·…·23시)으로 고른다. 그 발표본이 없으면 NA 로 두고 더 이른 발표본이나 관측값으로 대체하지 않는다.
  - 강수 변수: 2013-05-30 이전 `R12`, 2021-06-29 이전 `R06`, 이후 `PCP`. 정확한 전환 시각을 모르므로 전환일 ±3일은 두 변수를 모두 요청해 유효값이 있는 변수를 쓰고 기록한다.
  - `R12` 는 03·15시 시작 12시간 블록, `R06` 은 03·09·15·21시 시작 6시간 블록 값이며 블록 안 모든 대상시각에서 같은 값이 온다. `PCP` 는 대상시각에서 끝나는 1시간 값이다. `POP` 는 기술용.
  - 값은 받은 그대로 쓴다. 범주로 보이는 상한값(예: PCP 30·50)은 하한으로 취급하고 보정·보간하지 않는다.
  - 공식 제공범위 밖(전 격자 −99)은 "미제공", HTTP 오류는 재시도 후에도 실패하면 "수집 실패"로 구별해 기록한다.
    미제공 블록은 빼고 남은 연속창으로 계산한다. 수집 실패 블록이 하나라도 남은 발표본의 특징은 NA 로 둔다(일부 창만의 최댓값은 낮게 치우친다).
  - 전환기 두 변수가 모두 있는 발표본은 **창원 격자**에 유효값이 있는 변수를 쓴다.
- 창원 예보 격자: 분석 격자 75,400칸 중심점을 기상청 LCC 공식 변환으로 (nx, ny) 에 넣어 한 칸이라도 들어간 5 km 격자 전체. 응답 배열의 행 방향은 육지·바다 판별로 확정해 테스트로 남긴다.
- 호우특보 (API허브 `wrn_met_data.php`): 창원 특보구역 `L1080600` (2005-07-01~) 의 호우(R)·태풍(T) 특보. 발표·대치·해제 이력을 모두 보존한다.
- 원본은 `data/raw/kma/` 에 응답 그대로(gzip) 두고, 요청 인자·취득시각·SHA256 을 manifest 에 남긴다. 인증키는 어디에도 저장하지 않는다.
- 수집 범위: 라벨이 있는 사상 중 t0 ≥ 2010-07-01 인 사상마다 `tmfc ≤ t0 − 24h`, `tmfc ≤ t0 − 6h` 인 가장 늦은 예정 발표본의 발표 후 48시간.
- 매일 발표본으로 예보 기준 호우일을 정의하는 분석은 발령 임계·중복 경보 병합·검증창을 별도 문서로 고정하기 전에는 실행하지 않는다.

## 5. 1단계 — 사상 발생 확률

- 예보 특징 `r12max_fc(L)`: 선행 L 발표본에서, **(tmfc, tmfc+48h] 안에 완전히 들어가는** 블록만 써서 만든 창원 예보 격자별 12시간 누적의 최댓값.
  12시간 누적은 R12 블록 값, 연속한 R06 블록 2개의 합, 연속한 PCP 12개의 합이다. 관측 호우 종료시각 t1 은 쓰지 않는다.
- 모형 (특징 하나, 선택 없음): `logit P(E=1) = a + b·z`, x = log1p(특징), z = (x − 평균)/(2·표준편차), 평균·표준편차는 그 학습집합 값(ddof = 0).
  표준편차 0 이면 그 학습집합의 예측은 NA. 사전분포 Cauchy(0, 10) (절편), Cauchy(0, 2.5) (기울기), 사후 최빈값(L-BFGS-B) (Gelman 외 2008, doi:10.1214/08-AOAS191).
  수렴 실패는 그 학습집합의 예측을 NA 로 두고 보고한다. MAP 확률은 사후예측 평균이 아니다.
  - `M_fc24` (주), `M_fc6` (보조): 예보 특징
  - `M_obs`: `r12max_obs` 를 쓰는 **관측강우 비교모형** (시간·공간 해상도가 달라 예보의 상한을 보장하지 않는다)
  - `M_int`: 같은 사전분포의 절편 전용 모형 (수축 효과만으로 생기는 개선을 구별)
- 비교 기준
  - `B_clim`: 각 학습집합의 양성 수 / 사상 수 (V1 은 사상마다 다시 계산)
  - `B_rule110`, `B_rule180`: `r12max_fc(24)` ≥ 110 mm / ≥ 180 mm → 1, 아니면 0 (기상청 12시간 주의보·경보 기준)
  - `B_warn`: [t0 − 24h, t0] 에 창원 구역 호우·태풍 주의보 이상(명령 발표·대치·연장·변경)이 발표됨. 특보는 보통 수 시간 전 발표라 선행시간이 다르다.
- 검증
  - V1 사상 1개 제외 교차검증 (개발 사상 전체)
  - V2 발생연도순 후향 평가: 연도 y 사상을 y 이전 개발 사상으로 학습해 예측 (학습 양성 ≥ 2 인 해부터). 당시 자료 입수일은 확인하지 않았다.
  - V3 동결 홀드아웃 (주): 발생 모형·척도화·기후값을 **t0 ≤ 2019-12-31 개발 사상**으로만 고정해 2022~2024 사상에 한 번 적용.
    2025 사상까지 넣은 결과(V3b)는 별도 후향 분석으로만 보고한다.
- 모형 비교는 **같은 유효 사상 집합**(두 선행 예보 특징과 관측 특징이 모두 있는 사상)에서 한다. `M_obs`·`B_warn` 의 전체 사상 결과는 기술용으로 따로 싣는다.
- 지표: Brier 점수, BSS = 1 − Σ모형제곱오차 / Σ기준제곱오차 (V1 은 사상별 예측을 모아 한 번 계산하고 fold 별 BSS 를 평균하지 않는다. 기준오차 합이 0 이면 NA),
  사상 단위 ROC AUC, 신뢰도표 (구간 [0, 0.1), [0.1, 0.3), [0.3, 0.6), [0.6, 1.0]), POD·FAR·CSI (규칙 기준과, 모형 확률 ≥ 0.5 / ≥ 학습 발생률 두 기준).
- 불확실성: 모형과 기준의 사상별 예측을 **짝지어** 사상 단위로 재표집 (2,000회, seed 20260926, 백분위 2.5·97.5). 정의 불가 반복(양성 0 등)은 빼고 개수를 보고한다.
  고정된 교차검증 예측의 구간이므로 재학습 불확실성은 포함하지 않는다. POD 는 Clopper-Pearson 구간을 함께 싣는다.
- **주 판정 1**: V1 공통 유효 사상에서 `M_fc24` 의 BSS 하한 > 0 이면 "이 조건부 모집단에서 예보가 사상 발생에 기후값 이상의 정보를 준 증거"로 쓴다.
  실패는 "예보에 정보가 없다"는 증명이 아니다. V3 는 양성 4건이라 판정이 아니라 추정치로 쓴다.

## 6. 2단계 — 사상이 생겼을 때의 위치

- 공간 점수: 동결 RF-F1 파이프라인(`.omc/benchmark/final_model.joblib`, prespec `P005_dev_20260924T094916Z` 의 설정·특징)을 `clone` 해
  학습 사상 집합의 `trace_ev_<year>` 합집합 라벨로 전 격자(75,400칸, 완충 제외 없음)에 다시 적합한다. 강우는 넣지 않는다.
  (도시 안 강우 분포가 침수 위치와 역방향이었다는 홀드아웃 진단을 본 뒤의 선택이므로 `post-hoc` 설계로 표기한다.)
- V1, 개발 양성 사상 e 평가
  - 평가 점수 s^(−e): e 를 뺀 개발 사상으로 적합.
  - 보정 자료: e 가 아닌 개발 양성 사상 j 마다 점수 s_j^(−e,−j) (e 와 j 를 모두 뺀 사상으로 적합) 와 j 의 사상별 격자 라벨.
  - 기존 `predictions_loeo_<year>.npz` 는 학습 계보를 이 조건으로 입증하지 못해 쓰지 않는다.
- V1, 음성 사상: 모든 격자가 Y = 0 이다. 공간 점수와 보정은 개발 양성 사상 전체로 만든 것을 쓴다(음성 사상은 학습 라벨에 들어가지 않는다).
- V3: 공간 점수 = t0 ≤ 2019-12-31 개발 사상으로 적합(PAPER_ROADMAP 의 `model_frozen_to2019` 와 같은 설정). 보정 = 그 사상들 안에서 j 마다 j 를 뺀 점수로 만든 자료.
- 보정: q_i = σ(c + d·logit(s_i)), s 는 [1e-6, 1 − 1e-6] 로 자른다. 규제 없는 로지스틱, 격자 가중치 1.

## 7. 결합 평가와 시나리오 지도

- `P_it = p_t × q_i`. p_t 는 1단계 확률 (`M_fc24` 주, `M_obs`·`M_int` 비교, `B_clim` 기준).
- 평가 대상: 라벨이 있는 모든 사상 × 분석 격자 75,400칸. 음성 사상은 모든 격자가 Y = 0 이다.
- 지표: 격자·사상 전체 Brier 점수, 정적 기준 `B_clim × q_i` 대비 BSS, 사상 짝지은 붓스트랩 95% 구간.
  양성·음성 사상별 평균 Brier 와 전체에 대한 기여도, 사상별 침수 면적 오차(Σ_i P_it − 관측 양성 격자 수)를 함께 싣는다.
  양성 사상마다 격자 AUC·상위 20% 포착(동률은 grid_id 순)·**침수 객체(폴리곤) 1표 AUC** 를 싣는다.
- **주 판정 2**: V1 에서 `M_fc24 × q` 가 `B_clim × q` 보다 Brier 가 낮고 BSS 하한 > 0 이면 "예보를 넣은 **결합 확률의 Brier 개선**"으로 쓴다.
  p_t 는 사상 안의 격자 순위를 바꾸지 않으므로 "위치 예측이 좋아졌다"는 뜻이 아니다.
- 시나리오 지도 (보고서용, 평가 아님): 개발 사상 전체(2025 포함)로 적합한 모형으로 `r12max_fc` = 60 / 110 / 180 mm 일 때 `P_it` 를 격자로 그린다.
  등급은 고정 구간 (0.01, 0.05, 0.10, 0.20) 으로 나누고, 이 구간은 결과를 보지 않고 정했다.

## 8. 보고 원칙

- 모든 수치에 명령·run_id 를 붙인다. 판정 실패와 기존 정적 지수의 게이트 탈락을 그대로 싣는다.
- 격자 1표·침수 객체 1표·폴리곤 1표 결과를 함께 싣는다 (`AGENTS.md` §2-5).
- `M_obs` 와 `M_fc` 를 섞어 부르지 않는다.
- 2022~2024 사상은 "**결과와 일부 예보값에 사전 노출된 post-hoc 설계의 후향 평가**"로 부르고, 노출 내역은 §9 에 공개한다.
- 2026년 이후 봉인 평가는 창원시 2026년 흔적 자료가 없어 이번에 하지 않는다. 이 문서와 동결 모형을 새 사상에 그대로 적용할 수 있게 남긴다.
- 선행연구와 범위: 시민 침수 신고로 추정한 강우 임계 (Tian 외 2019, doi:10.1016/j.scitotenv.2019.06.355),
  배수망 모형 기반의 강우 사상 조건부 도시 내부 위치 확률 (Li·Willems 2020, doi:10.1029/2019WR025128),
  특정 호우의 영향 기반 예보 사례 (Rözer 외 2021, doi:10.1029/2020EF001851). 발상 자체의 최초성은 주장하지 않는다.
