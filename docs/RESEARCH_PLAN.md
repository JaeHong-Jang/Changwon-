## 0. 연구 전체 흐름 — 왜 이 연구를 하는가

### 0-1. 해결하려는 문제

이 연구의 출발점은 “비가 얼마나 오는가”가 아니다. 같은 양의 비가 와도 저지대·불투수면·
배수여건·인구·고령인구·대피 접근성에 따라 실제 피해는 다르게 나타난다. 따라서 핵심 질문은
다음과 같다.

> **기상청이 강한 비를 예보했을 때, 창원시의 어디에서 사람 피해가 커질 가능성이 높으며,
> 시는 언제·누가·무엇을 먼저 해야 하는가?**

기상 자체의 예측은 기상청 예보를 사용한다. 본 연구는 예보를 창원시 100m 격자의
`지역별 영향`과 `행동 가능한 선제조치`로 번역하는 의사결정 지원체계를 만든다.
기상청도 과거 피해이력·지형·배수처리·기상자료를 결합한 시군구 단위
[호우피해 가능성 예측정보](https://bd.kma.go.kr/kma2020/fs/preventionInfo.do)를 운영한다.
본 연구는 이 아이디어를 창원 내부 격자와 시민 민원·취약계층까지 세분화한다.

### 0-2. 연구가 연결해야 하는 전체 체인

```text
[과거 위험지식]
시민 민원·침수이력·행정답변 원문 봉인 + 파일 checksum
        │
        ▼
ID·접수일 등 메타데이터만으로 개발기간/최종기간 분리·checksum 동결
        │
        ├──────────────▶ 개발 원문만 LLM 구조화·표본검수·taxonomy 설계
        │                        │
        │                        └─ 추출기·prompt·model·taxonomy 버전 동결
        └──────────────▶ 최종 원문은 TOP 20 고정 뒤 같은 추출기로 1회 개봉·독립 검증

[지역 특성]                         [다가오는 호우]
지형·피복·하천·관로·인구·취약성     기상청 예보·선행강수
        │                                  │
        └──────────────┬───────────────────┘
                       ▼
          격자별 물리위험·예상피해·대응역량 계산
                       ▼
              우선대응지역 TOP 20
                       ▼
  시범 24시간 전 점검 → 시범 6시간 전 장비·인력배치 → 공식 판단 후 통제·대피지원
                       ▼
          실제 침수·새 민원으로 검증하고 다음 분석에 환류
```

이 흐름은 [UNDRR의 사람 중심 조기경보 4요소](https://www.undrr.org/terminology/early-warning-system)와 대응한다.

| 조기경보 요소 | 본 연구의 구현 |
|---|---|
| 재난위험 지식 | 민원 LLM·침수이력·지형·인구·배수 위험지도 |
| 탐지·감시·예보 | 기상청 예보·선행강수·격자별 호우 시나리오 |
| 행동 가능한 경보 전달 | 위험등급·원인·신뢰도·담당부서 알림 초안 |
| 대비·대응 | 빗물받이 점검·펌프/인력 배치·도로통제·취약주민 대피지원 |

따라서 연구는 위험지도를 만드는 데서 끝나지 않는다. `위험지식 → 예보 → 지역별 영향 →
현장 행동 → 사후학습`을 하나의 닫힌 고리로 만드는 것이 최종 목적이다.

### 0-3. 민원 LLM은 Layer 0이다

민원 LLM 분석은 부가 기능이 아니라 연구의 **위험지식 계층**이다. 단, 원문 분석보다
홀드아웃 봉인이 먼저다. 원본 파일 checksum을 기록하고 ID·접수일 등 의미내용을 보지 않아도
되는 메타데이터만으로 개발/최종 기간을 나눈다. 개발 원문만 아래 구조로 변환해 표본검수하고,
추출기 코드·prompt·model·taxonomy 버전을 동결한다. 최종 원문은 지수식·가중치·TOP 20을
고정한 뒤 같은 추출기로 한 번만 처리한다.

| 필드 | 의미 |
|---|---|
| `occurred_at`, `location_text`, `geometry` | 언제·어디에서 발생했는가 |
| `complaint_type` | 도로침수·주택침수·하수역류·배수불량·기타 |
| `affected_target` | 사람·차량·주택·상가·도로 |
| `cause_candidate` | 저지대·빗물받이·관로·하천 등 원인 후보 |
| `requested_action` | 시민이 요구한 조치 |
| `department_response`, `promised_action` | 담당부서 답변과 예정 조치 |
| `evidence_span`, `confidence`, `reviewed` | 추출 근거·신뢰도·사람 검수 여부 |

민원 LLM의 역할은 네 가지다.

1. 개발 민원에서 반복 침수·역류 위치와 문제유형을 발견한다.
2. 개발 민원으로 어떤 공간변수를 분석해야 하는지 가설을 만든다.
3. 동결한 최종기간 민원을 동일한 추출기로 1회 처리해 위험지도와 TOP 20을 독립 검증한다.
4. 개발 민원의 시민요구와 실제 행정답변을 연결해 실행 가능한 정책 후보를 만든다.

같은 민원을 지수 입력과 최종 평가에 동시에 사용하지 않는다. 개발기간 민원은 유형정의·EDA·
가설설계에만 쓰고, 최종 홀드아웃 민원은 공식·가중치·TOP 20과 추출기를 고정한 뒤 한 번만 연다.
민원 부재를 곧바로 비침수로 간주하지 않으며 신고성향 편향과 위치오차를 함께 기록한다.

### 0-4. 왜 Hazard·Exposure·Vulnerability·Capacity를 나누는가

IPCC는 기후위험을 기후 관련 위험요인(Hazard), 노출(Exposure), 취약성(Vulnerability)의
[동적 상호작용](https://www.ipcc.ch/report/ar6/wg2/chapter/technical-summary/)으로 설명하고,
[UNDRR](https://www.undrr.org/terminology/disaster-risk)는 여기에 대응역량(Capacity)을 함께 평가한다. 이는
“비가 많이 오는 곳”과 “사람 피해가 클 곳”이 같지 않기 때문이다.

| 요소 | 이 연구에서 묻는 질문 | 대표 변수 |
|---|---|---|
| Hazard | 실제로 물이 고이거나 역류할 가능성이 높은가 | 예보강수·선행강수·상대고도·경사·불투수면·하천·관로 |
| Exposure | 문제가 생기면 피해 대상이 얼마나 많은가 | 총인구·건물·도로·상가 |
| Vulnerability | 같은 노출에서도 더 큰 피해를 입을 가능성이 있는가 | 고령인구·지하층·노후건물 |
| Capacity | 시와 주민이 얼마나 빠르게 대응할 수 있는가 | 펌프 서비스·대피소·긴급대응 접근성·현장인력 |

현재 `CDRI`는 IPCC·UNDRR이 정한 국제 표준명이나 단일 공식이 아니다. 본 연구에서 정의하는
**창원형 도시침수 선제대응 우선순위지수**의 작업명이다. 따라서 다음처럼 사용한다.

```text
물리적 침수위험 H = f(예보강수, 지형, 피복, 하천, 관로·배수조건)
예상 피해영향     = f(H, Exposure, Vulnerability)
정규화 대응역량 C  = 높을수록 대응능력이 좋음
대응역량 부족도 D  = 1 - C (높을수록 우선대응 필요)
선제대응 우선순위 = 예상 피해가 높고 D가 큰 지역
```

Capacity 결측은 0 또는 최대부족으로 임의 대체하지 않는다. 해당 변수를 제외해 가중치를
재정규화하고 신뢰등급을 낮추며, 결측률과 제외 사유를 공개한다. 곱셈형과 가중합형은 둘 다
비교하되, 산식·가중치 선택은 **개발세트 내부의 시간·공간 검증과 민감도 분석만으로** 끝낸다.
최종 홀드아웃은 이미 고정된 단일 primary 산식의 확인적 평가에만 한 번 사용한다.
펌프장도 단순 거리는 대응역량 후보로 두고, 실제 용량·서비스권역·가동효과가 확보된 경우에만
물리적 배수능력 변수로 사용한다. 어느 경우에도 여러 Layer에 중복 투입하지 않는다.

### 0-5. 머신러닝은 조건부 비교모델이다

주 분석은 데이터가 부족해도 완성 가능한 동일가중 우선순위지수다. 실제 침수·비침수의
위치·날짜가 여러 호우 이벤트에 걸쳐 충분히 확보된 경우에만 다음 지도학습 모델을 비교한다.

```text
X = 예보강수 + 선행강수 + 지형 + 피복 + 하천 + 관로·배수조건
Y = 해당 호우 때 해당 격자가 실제 침수·역류했는가
```

- 기준모델: 로지스틱 회귀
- 비교모델: XGBoost + SHAP
- 평가: 호우 이벤트·연도·공간 block 분리 F1·PR-AUC

양성 민원만 있고 검증된 음성 라벨이 없으면 임의 격자를 비침수로 만들지 않는다. 이때는
확률예측을 주장하지 않고 우선순위지수의 상위 10/20% 적중률과 무작위 대비 lift를 보고한다.

### 0-6. 정책 제안은 ‘문장’이 아니라 트리거-행동 계약이다

TOP 20마다 다음 필드를 갖춘 정책카드를 만든다.

| 필드 | 질문 |
|---|---|
| 대상 | 어느 격자·도로·시설·취약가구인가 |
| 근거 | 강수·지형·민원·인구 중 무엇이 위험을 높였는가 |
| 트리거 | 어떤 예보·현장관측·신고 조건에서 행동하는가; 공식 SOP 확인 전 시간기준은 시범 시나리오로 표시 |
| 시간 | 우기 전, 24시간 전, 6시간 전, 위험 현실화 중 언제인가 |
| 행동 | 점검·준설·장비배치·통제·연락·대피지원 중 무엇인가 |
| 주체 | 재난·하수·구청·복지·경찰·소방 중 누가 판단·실행하는가 |
| 자원·비용 | 기존 인력·이동식 장비·소규모 정비·중장기 시설사업 중 무엇인가 |
| KPI | 점검완료율·연락률·통제 선행시간·반복민원·피해가 줄었는가 |
| 신뢰·승인 | 데이터 신뢰등급과 사람의 최종 승인 지점은 어디인가 |

정책은 시간대별로 구분한다.

| 시점 | 목적 | 가능한 조치 예시 |
|---|---|---|
| 우기 전 | 구조적·운영적 예방 | 반복민원지역 준설, 관로·펌프 점검, 책임관리자·대피지원대상 갱신 |
| 예보 24~48시간 전 | 대비 | TOP 20 재점검, 이동식 펌프·차수판·인력·통제장비 준비 |
| 예보 3~6시간 전 | 피해 회피 | 취약가구 연락, 현장배치, 지하차도·하천변 선제통제 후보 상신 |
| 위험 현실화 | 인명보호 | 공식 판단에 따른 위험구역 설정·통제·대피명령·이동약자 지원 |
| 호우 후 | 학습·개선 | 실제 침수·민원·조치결과 수집, 오탐·누락 분석, 지수·행동규칙 갱신 |

시스템은 자동으로 통제나 대피명령을 발령하지 않는다. `24시간 전·6시간 전` 같은 기준도
담당부서의 공식 SOP로 확인되기 전에는 **공모전 시범 시나리오**라고 표시한다. 위험지역·원인·신뢰도·권장조치와
현장 확인사항을 제공하고, 법적 권한을 가진 담당자가 공식 예보·현장정보를 함께 확인해
최종 결정한다.

### 0-7. 공모전에서 가능한 범위와 주장하지 않을 것

| 구현·검증 가능한 것 | 현재 데이터만으로 주장하지 않을 것 |
|---|---|
| 민원 LLM 구조화와 반복문제 지도 | 100m별 정확한 실시간 침수수심 |
| 정적 취약지도와 예보 시나리오별 동적 위험지도 | 검증자료 없는 침수확률 |
| TOP 20·위험원인·신뢰등급·정책카드 | 자동 대피·통제 결정 |
| 담당부서 점검목록과 알림 초안 | 센서·수리모형 없는 실시간 침수 확정 |
| 실제 민원·침수이력 홀드아웃 검증 | 관로자료가 없는데 만든 정밀 역류모델 |

최종 핵심 산출물은 `민원 위험지식 지도 + 정적 취약지도 + 호우 시나리오 지도 + TOP 20
정책카드`다. 일정에 여유가 있을 때만 고정된 TOP 20과 정책카드를 조회해 담당자 알림 문안
1건을 만드는 선택적 출력 예시를 추가하며, 시민 챗봇·자동발송·자동대피는 구현하지 않는다.

사후 침수·민원·조치결과는 `feedback_version`과 수집시각을 붙여 다음 모델 버전의 개발자료로만
편입한다. 이미 보고한 최종 홀드아웃 성능을 새 데이터로 다시 계산해 같은 성능처럼 덮어쓰지
않으며, 이번 공모전에서는 피드백 스키마와 버전 전환 절차까지를 구현 범위로 한다.

## 0-A. 하네스 구조란

이 계획은 "할 일 목록"이 아니라 **증거 게이트로 연결된 스토리 체인**입니다.

단계별 실행·중단·복구 규칙과 최신 데이터 품질 기준은
[`RESEARCH_HARNESS.md`](RESEARCH_HARNESS.md)를 실행 원천으로 사용합니다. 원본 계약은
`config/data_contracts.yaml`, 검증 실행은 `src/data/validate_raw.py`에 있습니다.

```
Story N  ──[증거 제출]──▶  checkpoint  ──▶  Story N+1 활성화
              │
              └─ 증거 없으면 완료 불가 (goals.py가 거부)
```


| 원칙                                      | 구현                               |
| --------------------------------------- | -------------------------------- |
| 각 스토리 = 목표 + 입력 + 산출물 + **검증 기준**       | 이 문서 §4                          |
| 다음 스토리는 이전 스토리 checkpoint 후에만 시작        | `goals.py next`                  |
| 완료 주장에는 반드시 증거(파일 경로·수치·로그)             | `goals.py checkpoint --evidence` |

| 분기점(Decision Gate)은 증거 기반으로 Plan A/B 선택 | G006                             |
| 최종 스토리는 검증 명령 없이 완료 불가                  | `--verify-cmd` 게이트               |
| 상태는 파일로 영속화 → 세션·사람이 바뀌어도 이어감           | `.fablize/goals.json` + git      |

## 2. 연구 설계 (확정)

### 2-1. 주제 확정문 · 연구 질문

**주제명**: 창원시 폭우 침수·하수 역류 우선 대응지역 분석 — 100m 격자 통합위험지수(CDRI) 기반 TOP 20 선정
**한 문장**: 강수·하천수위·배수펌프장·하수관로·민원·인구·건물 데이터를 100m 격자로 결합해 침수×역류×취약계층 통합 위험지수를 산출하고, 폭우 시 먼저 점검·대응할 지역 20곳과 그 이유(기여도)를 제시한다.

> 폭우 시 창원시에서 **침수·하수 역류 위험이 높고 취약계층이 밀집한 격자**는 어디이며(TOP 20), 그 우선순위를 하수도사업소·재난안전 부서가 **점검·대응 순서**로 어떻게 쓸 수 있는가?

1. 실제 민원에서 반복되는 침수·역류의 위치·원인·시민요구·행정조치는 무엇인가?
2. 기상청 호우예보가 주어질 때 물리적으로 침수·역류 가능성이 높은 100m 격자는 어디인가?
3. 그중 사람·건물의 노출과 고령자·지하층 등 취약성이 커 예상 피해가 큰 곳은 어디인가?
4. 예상 피해가 크고 대응역량이 부족한 TOP 20에 대해 어떤 부서가 언제 무엇을 해야 하는가?
5. 새 민원·실제 침수·조치결과를 어떻게 다음 예보와 정책에 환류할 것인가?

### 2-2. 분석 프레임 — 민원 위험지식 + 국토부 지침 + IPCC·UNDRR

```
공간 단위: 100m 격자 (국토부 2024 개정 지침의 공간구조 참고, SGIS 격자인구와 직접 결합)

Layer 0  민원 위험지식 = 원문 접근 전 메타데이터 분리·checksum 동결
                       개발 원문으로 LLM 장소·유형·피해·원인·시민요구·행정답변·근거문장 구조화
                       추출기·taxonomy 동결 후 최종 원문은 TOP 20 고정 뒤 1회 처리·평가

Layer 1  침수 취약성  = 기후노출(강우 IDW 보간) × 민감도(저지대·경사·불투수면·하천버퍼·배수조건)
Layer 2  역류 위험    = Plan A: 관로 경과연수·관경·재질·밀도 + 강우 → ML(타깃=확인된 개발기간 역류·침수 라벨)
                       민원은 검수된 양성 후보일 뿐이며 민원 부재를 음성으로 간주하지 않음
                       최종 홀드아웃 민원·침수이력은 학습·튜닝에 쓰지 않고 평가에만 1회 사용
                       Plan B: 합류식비율·관로밀도·저지대 → 우선점검 지수
                       관로 집계도 없으면 Layer 2를 제외하고 CDRI 민감도만 보고
Layer 3  예상 피해    = Exposure(총인구·건물) + Vulnerability(고령·노후건물·지하층)
Capacity 대응역량 C   = 펌프 서비스·대피소·긴급대응 접근성·현장지원 가능성(높을수록 좋음)
Capacity 부족도 D     = 1 - 정규화(C), 높을수록 우선대응 필요
                       ※ 1인가구는 현재 미보유이므로 추가 확보 전 수식에서 제외

통합     CDRI = 본 연구의 창원형 도시침수 선제대응 우선순위지수(공식 표준명·공식 산식 아님)
         Hazard(L1+가용 시 L2), Exposure, Vulnerability, Capacity deficit(D)를 결합
         → 0~1 정규화 → Balica 5등급 → TOP 20 격자 + 기여도 분해(침수/역류/취약/대응부족 %)
산식     곱셈형과 가중합형을 baseline/challenger로 비교; Layer 2 미보유 시 남은 항목 재정규화
         Capacity 결측은 0으로 두지 않고 제외·재정규화하며 신뢰등급 하향
가중치   연구팀 baseline인 동일가중 + 엔트로피·입력오차 시나리오 → 순위 상관(Spearman) 보고
         AHP는 전문가 응답과 일관성 검증을 실제 확보한 경우에만 추가
검증     민원·침수 원문이나 LLM 결과를 보기 전에 메타데이터만으로 개발/최종 홀드아웃 분리·checksum 동결
         Layer 1·2 개발: 개발세트 내부 호우·연도·공간 block 검증; 선행연구 사례지는 face-validity만
         최종 평가: 지수식·가중치·TOP 20·추출기 동결 뒤 최종 홀드아웃을 1회 개봉해 적중률·lift 평가
정책     TOP 20마다 트리거·시간·행동·담당·자원·KPI·신뢰등급·사람 승인 지점을 명시
```

### 2-3. AI 요소의 자리 (분석 도구 우선, 장식 금지)

| 요소 | 성격 | 보고서 위치 | 검증/측정 |
|---|---|---|---|
| **민원 텍스트 LLM 구조화** (`classify_complaint`) | 개발 민원에서 장소·유형·피해·원인후보·시민요구·행정답변·근거문장을 추출하는 분석 도구 | **3장 방법론** | 수작업 100건 대비 필드별 정확도·사람검수율 |
