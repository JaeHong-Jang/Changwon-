## 2. 방향 조정 (결정 기록 001 로 확정 예정)

현재 계획의 약점은 "데이터가 세상에 없어서"가 아니라 대부분 **아직 신청·다운로드를 안 해서** 생긴 것이다.
회신으로 사라진 두 자리(민원·관로)는 침수흔적도와 공개 자료로 메운다.

1. **보고서의 주인공을 Layer 1 로 옮긴다.** 강수 노출 × 지형·피복 × 시 침수예상도 → 침수취약 격자.
   9/14 침수흔적도로 AUC 와 사후검증을 하고, "2020~2023 실제 침수 N건 중 M건을 상위 20% 가 포착"을
   보고서의 첫 숫자로 쓴다. 원래 민원 홀드아웃이 맡던 "이익 증명" 역할을 침수흔적도가 대신한다.
2. **Layer 2 는 보조 지표로 강등한다.** 읍면동 관로 집계를 격자에 뿌린 값을 "하수역류 위험"이라 부르지
   않는다. 배수구역 폴리곤으로 해상도를 올리고, 침수흔적도의 침수 원인(내수·하수) 항목과
   자연재해저감계획 내수 위험지구 13개소로만 대조한다. CDRI 가중치에서 빼는 안을 기본으로 민감도 1회.
3. **Layer 3 는 인구·고령·대피소 거리를 기본으로, 건물(지하층·노후)은 키 발급 후 추가한다.**
   결과는 "TOP 20 안 65세 이상 N명, 대피소 2km 밖 M명"이라는 사람 수로 쓴다.
4. **트리거 시간(24h·6h)은 근거가 없으므로 공식 기준으로 바꾼다.** 행안부 풍수해 위기관리 표준매뉴얼
   4단계(관심·주의·경계·심각)와 기상청 호우특보 기준(주의보 3h 60mm / 12h 110mm, 경보 3h 90mm / 12h 180mm).
   침수흔적 날짜와 시간별 강수를 맞춘 "시간당 N mm 에서 잠긴 지구" 관측 임계치를 병기한다.
5. **AI 는 두 자리로 한정한다.** ① 침수흔적 라벨로 Layer 1 XGBoost·SHAP 비교모델(라벨이 생기므로
   하네스 규칙상 허용) ② 시민의소리 공개 게시글 LLM 구조화 — 표본 50건 중 위치가 잡히는 비율이
   50% 미만이면 제외한다. 결정 002(AI 는 분석 도구로만)는 유지.
6. **파이프라인 반영**: `h05_holdout_freeze`·`h05_complaint_extract` 를 optional 로 전환,
   `h06_layer1_flood` 의 `evaluation_points.gpkg` 입력을 선택 입력으로, Layer 2 가중치 강등을 `config.yaml` 로.

연구 질문(하네스 §1) 다섯 개 중 **1번(민원에서 반복되는 침수·역류)은 이의신청이 성공하지 않는 한 답할 수
없고**, 4번의 "언제"는 SOP 대신 공식 특보 기준으로 답한다. 이 축소는 보고서 한계 절에 그대로 쓴다.
