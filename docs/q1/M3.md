## 결과 요약

- **사전 판정: 설정 선택의 미래 정보가 격자 AUC 중앙값을 0.02 넘게 올리지 않았다.** E_nest 6사상 격자 AUC 중앙값은 중첩 RF 0.865, 고정 구성 walk-forward 0.873 이다 (차 0.008). 사상별 짝 차이(고정 − 중첩)의 중앙값은 −0.002 다.

## 한계·미확인

- **post-hoc.** M1·홀드아웃 결과를 본 뒤 설계했다. 홀드아웃은 선택·학습에 쓰지 않았다.
- **사상 수가 적다.** E_nest 6사상 중 3사상(2025·2023-08·2024-09)은 같은 P 의 같은 선택을 공유한다. 독립적인 선택은 4번이다.
  판정은 중앙값 차이 0.008 과 규칙 여유 0.012 에 기댄다. 사상 하나가 바뀌면 판정이 바뀔 수 있다. 사상 수준 통합은 M2 에서 한다.
- **선택이 불안정하다.** 1위와 고정 구성의 안쪽 점수 차이가 0.0001~0.0057 이다. 다른 시드나 다른 선택 지표(격자 AUC)라면 다른 설정이 뽑혔을 수 있다. 확인하지 않았다.
- **격자 자체의 미래 정보는 남는다.** 특징 후보군(F0/F1/F2)과 모델 후보 격자는 홀드아웃 진단 뒤에 정했다
  (`walkforward_20260926T135215Z_3d14fc1/summary.json` `role`). M3 는 이 격자 **안의** 선택만 시간순으로 만든다.
- 안쪽 선택 지표는 `cluster_auc` (벤치마크 선택 규칙과 같음)이고, 바깥 주 판정 지표는 격자 AUC 다.
- 2012 는 선택 불가라 중첩 비교에서 빠진다. M1 에서 RF 가 가장 낮았던 사상이다 (0.780).
- **공식 run 전 실행 1번.** 코드 커밋 전에 실행 흐름 점검을 한 번 했다. 개발 전용, 설정 2개(RF/F1 두 후보)로 줄인 격자, `n_boot` 20 이었고,
  산출은 scratchpad 에 두고 저장소에 넣지 않았다. 이 점검에서 개발 전용 모드의 M1 재현 확인이 객체 AUC 행에서 실패했다.
  원인은 개발 전용 모드가 홀드아웃 흔적을 비접촉 배경에서 빼지 않는 데 있다 (M1 공식 run 과 배경이 다르다).
  그래서 **개발 전용 모드에서만** 격자·덩어리 단위로 비교하게 고쳤다. 공식 run(홀드아웃 포함)은 절차대로 모든 단위를 비교했다 (473행 일치).
  이 점검의 설정 2개는 모두 RF/F1 이라 M3 의 선택·판정과 무관하다.
- 절차 §6 파일 목록에 없던 `m3_checks.py` 를 따로 만들었다 (재현 확인 기능, AGENTS §6-2). 분석 내용의 변경은 아니다.

1. **논문 표현.** 제안: "RF-F1 walk-forward 수치(M1)는 특징집합·하이퍼파라미터 선택을 시험 사상 이전 사상으로 제한해도 격자 AUC 중앙값이 0.008 낮아지는 데 그쳤다 (사전 규칙 0.02 이내).

2. **F0 대 F1.** 이전 사상만으로 고르면 네 번 모두 시 침수예상도 깊이를 뺀 F0 이 뽑힌다 (차이는 작다). 고정 구성이 F1 인 것은 전체 개발 CV(미래 사상 포함)의 선택이다.
   시 침수예상도를 특징으로 쓰는 서술에 이 사실을 함께 적을 것을 제안한다.
3. **M2 입력.** M2 대상 점수는 "M1 과 같다". 이 run 의 `metrics_long.csv` 에 `nested_rf`·`nested_all` 이 있어, M2 에 추가할지 정해야 한다.
